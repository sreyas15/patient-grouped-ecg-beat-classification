# R2 Experimental Protocol

Status: **APPROVED by the authors on 2026-11-02 (decisions D1–D7 and additional requirements R1–R10, §10–§11).** No model had been trained under this protocol at approval. On locking, the split file, this protocol, the configuration and all experiment-code hashes are written to `revision/R2/locked_protocol.json` *before* any outer test fold or external dataset is scored. The test-scoring script refuses to run if those hashes have changed.

Evidence for every statement below is in `revision/R2/results/data_audit/` and `revision/R2/results/splits/`, generated by `revision/R2/experiments/01–03_*.py` (logs in `revision/R2/logs/`).

## 3. Partitioning (approved D5; frozen as `results/splits/folds_LOCKED.json`, identical fold content to `proposed_folds.json`)

**Design: nested, subject-grouped 5-fold cross-validation.** Each subject is tested exactly once, by a model whose training, hyper-parameter selection, checkpoint selection and temperature never involved that subject. For outer fold *k*: test = fold *k*; validation = fold (*k*+1) mod 5; training = the other three folds.

The assignment uses only per-subject label counts (no model outputs). It was generated by `02_design_splits.py` (seed 20261102; best of 200,000 random assignments, 17,546 of which were feasible) under these pre-specified constraints:

- H1: the four paced subjects are in four different folds;
- H2: records 208 and 213 are in different, cyclically **non-adjacent** folds, so at least one is always in training;
- H3: every fold contains S and V beats.

Known weaknesses, to be reported:

- per-fold F metrics are unreliable in folds with 11–36 test F beats;
- validation F counts are tiny in outer folds 0 and 2, so checkpoint selection for F is noisy;
- outer fold 2's validation set holds only 5 Q beats, and outer fold 3's test holds 5;
- the **primary MIT-BIH result is therefore the pooled out-of-fold prediction set**, with subject-cluster bootstrap CIs. Per-fold results are secondary.

## 4. Signal pipeline (identical for all three models, MIT-BIH, INCART, PTB-DB and the clinical pipeline)

1. Lead (**D3 approved**): **MLII where available** (channel 0, or channel 1 for record 114); **V5 for records 102 and 104**, which have no MLII. This affects 4,408 of 109,305 beats, all in two of the four paced subjects; it is documented as a lead difference and a Q-class confound. External data use lead II.
2. Resample to 360 Hz if needed (`scipy.signal.resample_poly`; INCART 257 → 360, PTB-DB 1000 → 360).
3. Denoise with the original `denoise()` (db5, level 9), unchanged. The manuscript text is corrected to describe it accurately.
4. **Per-record z-score** of the denoised lead (matches manuscript Eq. 5; uses only that record's own samples, so there is no cross-subject leakage).
5. Beat window R−99 … R+200 at 360 Hz (300 samples = 833 ms; R-peak at index 99), centred on the reference annotation (MIT-BIH, INCART) or on detected R-peaks (PTB-DB, clinical input).
6. Model input (**D1 approved**): **identical 186-sample tensors for all three models**. The 300-sample window is resampled to 186 samples (same 833 ms, effective 223.2 Hz; `scipy.signal.resample`). Model C requires this length, because its Transformer `d_model = 25` equals the number of time steps after pooling. Model A's FC layer fits 186 natively. Model B's dense layer is resized (24 × 32 inputs instead of 38 × 32): 451,361 parameters at 186 samples, versus 508,705 at 300, which matches the Keras original exactly.

**No preprocessing parameter is fitted across records or subjects (R1).** Denoising is a fixed transform. The z-score uses only the recording's own samples, and is equally available at inference. Resampling is deterministic. No label enters preprocessing. The only fitted data transformation, SMOTE, is fitted on the training partition only.

## 5. Training and selection (identical for all models; PyTorch)

- Models:
  - A = `arrhythmia_cnn.py` architecture;
  - B = PyTorch port of the Keras CNN-LSTM-Attention (`revision/exp.py`, 508,705 parameters at 300 samples). It is stated to be a port, not the published Keras weights;
  - C = ECGTransForm, unchanged.
- Class balancing: SMOTE (k = 5), training partition only, after any z-scoring. N is randomly subsampled to the target; S, V, F and Q are oversampled to the target. The **target is fixed a priori at 20,000 per class (D2 approved)**: a pre-specified, compute-driven choice. It differs from the manuscript's 50,000, is not compared against other targets, and is not optimised. Validation and test keep their natural distribution.
- Loss: unweighted cross-entropy (the training data are balanced). Optimiser: Adam, batch 128, weight decay 1e-4.
- Hyper-parameter grid (pre-specified, small): learning rate ∈ {1e-4, 5e-4, 1e-3}. Epoch budget: A 15, B 20, C 15.
- Selection, per outer fold, using **that fold's validation partition only**:
  - learning rate and checkpoint epoch maximise validation macro-F1, computed over classes with ≥ 10 validation beats (the classes used are recorded);
  - temperature T is then fitted by NLL on the selected checkpoint's validation logits.
- Seeds: one training seed per fold (1000 + k), identical across models. Fold-to-fold variation is reported; seed repeats are optional if time permits.
- Compute (measured in the smoke test, `logs/00_smoke_test.log`, 100,000 SMOTE beats per epoch): A ≈ 2 s, B ≈ 6 s, C ≈ 87 s per epoch. **Total ≈ 6 GPU-hours** (C ≈ 5.4 h).
- Logged per run:
  - config;
  - split hash;
  - per-epoch validation metrics, with no test metrics computed during training;
  - selected checkpoint and T;
  - validation logits.

Test logits are produced by a separate scoring script, run once, after `locked_protocol.json` exists.

| Unmapped | `n` (supraventricular escape) 32, `B` (bundle-branch-block beat, unspecified) 1. They are dropped under the original mapping and disclosed (33 beats) |
| Class spread by patient | S in 19 patients (57% from patient 15); V in 31; F in 14 (219 beats, at most 26% from one patient); Q in 4 patients (6 beats) |
| R-annotation alignment (proxy = argmax \|x − median\| within ±75 ms, after 257 → 360 Hz) | **N:** INCART median 0 ms, 5th–95th pct −19 to +19 ms, 85% within ±14 ms; MIT-BIH −3 to +6 ms, 98%. **V:** INCART median +14 ms, 51% within ±14 ms; MIT-BIH median 0, 57%. The proxy itself is unreliable for wide or biphasic V complexes on both databases. **S, F:** comparable or better. INCART beat locations are therefore looser than MIT-BIH's (by up to about 7 samples at 360 Hz for N) and slightly shifted for V. With the R−275 ms … R+558 ms window, the QRS stays inside the window |

**Recommendation: accept INCART as the independent external test set for N, S, V and F, with these pre-specified conditions:**

1. **Q is not externally evaluable** (6 beats, no paced patients). External macro-F1 is pre-specified over **N, S, V, F**. The full 5 × 5 confusion matrix is still shown, and false Q predictions are counted as errors.
2. Primary analysis uses the reference annotations as given, which mirrors MIT-BIH. A pre-specified **sensitivity analysis** re-centres each window on the signal-based peak proxy within ±75 ms. This uses the signal only, never labels or predictions.
3. Lead II, 257 → 360 Hz `resample_poly(360, 257)`, the same denoising, per-record z-score, window, and first-2/last-3 edge rule as MIT-BIH.
4. F external results rest on 219 beats from 14 patients and S on 1,960 beats dominated by one patient. Wide CIs are expected and will be reported as such.
5. INCART is used **once**, after locking, for scoring only: no training, tuning, threshold, temperature or model selection. The scoring script is the same one used for MIT-BIH test folds.

## 7. Evaluation (pre-specified)

- **Classification:**
  - per class: sensitivity, specificity, PPV (precision), F1, AUROC and AUPRC (one-vs-rest);
  - overall: macro-F1, accuracy, balanced accuracy;
  - confusion matrices (counts and row-normalised).
- **Uncertainty:** 95% percentile CIs from a **subject-cluster bootstrap** (2,000 resamples of subjects: 47 MIT-BIH; INCART patients per the audit). The number of subjects and beats contributing to each class is reported next to every per-class metric.
- **Calibration:** reported before and after temperature scaling, with definitions written out in the manuscript:
  - top-label ECE (15 equal-width bins, |accuracy − confidence|, weighted by bin size);
  - **signed** calibration gap (mean confidence − accuracy, overall and per bin), used before any over- or under-confidence claim;
  - MCE;
  - class-wise one-vs-rest ECE;
  - multiclass Brier score;
  - NLL;
  - reliability diagrams.
- **Model comparison:**
  - primary: paired subject-cluster bootstrap of the difference in macro-F1, and per-class sensitivity, on identical beats;
  - secondary: exact McNemar test on identical beats, with discordant counts, test statistic and p-value. It is labelled approximate because beats are clustered within subjects.
  - No significance claims on per-fold numbers.
- Nothing is computed on a test partition until every fold model is locked.

## 8. Downstream analyses (protocol fixed before computing; detailed in later stages)

- **PTB-DB:** domain-transfer analysis with a different endpoint (Stage 4), on raw PTB-DB 1.0.0, lead II, 1000 → 360 Hz, detected R-peaks. Reported:
  - top-1 AAMI class distribution per diagnostic group;
  - a beat-level binary confusion matrix (N vs non-N) against record-level labels, explicitly labelled non-equivalent;
  - healthy-control false-alarm rate with a patient-cluster bootstrap.
- **XAI (Stage 5):**
  - IG with the **zero baseline** as primary, because it is the deployed default and was not selected on test data. Mean-beat and Gaussian baselines are reported as a descriptive sensitivity analysis only;
  - Grad-CAM on the last convolutional layer;
  - landmark reference regions defined in ms relative to R and committed to a file **before** any attribution is computed;
  - metrics: overlap, IoU, peak distance, widths;
  - correct vs FP vs FN beats, sampled with a fixed seed;
  - a random-attribution comparator.
- **DTW (concern #8):** recomputed descriptively on the SMOTE output of each training partition, with no pass/fail threshold.
- **Clinical pipeline (Stage 6):** R-aligned beats, the same denoising and normalisation, sampling-rate check, thresholds aligned with the text; runtime re-measured on real held-out MIT-BIH recordings.

## 9. Deviations from the original manuscript (to be disclosed)

1. Patient-grouped nested CV replaces the beat-level splits.
2. One common data pipeline replaces three different ones (Kaggle 125 Hz CSV for A and C, raw 360 Hz for B).
3. Model B is a PyTorch port.
4. Model C is trained for 15 epochs, not 60.
5. Loss and balancing are unified (SMOTE plus unweighted CE for all models), replacing none / SMOTE / class-weighted CE.
6. MLII is used for record 114, instead of channel 0 (V5).
7. The Table 4 SMOTE/ADASYN ablation and the Table 7 baseline selection are withdrawn as selection evidence.
8. SMOTE target 20,000 per class (D2) instead of the manuscript's 50,000.
9. Model B input is 186 samples (D1) instead of 300 (dense layer resized; 451,361 parameters).
10. MIT-BIH records 102 and 104 use lead V5 (no MLII available).

## 10. Approved decisions (authors, 2026-11-02)

- **D1** Identical 186-sample inputs for Models A, B and C.
- **D2** SMOTE target 20,000 per class: pre-specified for computational feasibility, never compared or optimised on test performance.
- **D3** MLII wherever available; V5 for records 102 and 104, explicitly documented.
- **D4** INCART is evaluated with the ensemble (mean temperature-scaled softmax) of the five locked fold models. No additional all-subject model is trained.
- **D5** The patient-grouped five-fold assignment in §3 is approved, frozen and hashed before training (`results/splits/folds_LOCKED.json`). It is never redrawn on the basis of any model performance or test result.
- **D6** INCART is approved as the independent external evaluation set. Its limitations are preserved, and the primary external macro-F1 is computed over N, S, V and F only.
- **D7** Original INCART annotations are primary; peak re-centring is a sensitivity analysis.

## 11. Additional requirements (R1–R10) and how they are enforced

| # | Requirement | Enforcement |
|---|---|---|
| R1 | Preprocessing, SMOTE and normalisation fitted on training data only | No cross-record parameters exist (§4). SMOTE is called on the training mask only (`06_train.py`); `config.json` records `smote_applied_to` |
| R2 | Validation alone controls checkpoint and calibration | `r2common.train_one` selects on validation macro-F1; `fit_T` uses validation logits; the test mask is never used to slice data in `06_train.py` |
| R3 | Freeze architectures and settings before final evaluation | `locked_protocol.json` hashes data, folds, protocol and all code (incl. upstream ECGTransForm `models.py`/configs). `verify_lock.py` aborts training and scoring on any mismatch |
| R4 | No best-model selection on pooled OOF results | **Primary model = B, pre-specified** (the manuscript's clinical-pipeline backbone); A and C are comparators. Pre-specified comparisons: B−A and B−C. A−C and any ranking statement are labelled exploratory |
| R5 | Patient-level CIs and class-wise metrics | Subject-cluster (MIT-BIH, 47) and patient-cluster (INCART, 32) bootstrap, 2,000 resamples. Per-class sensitivity, specificity, PPV, F1, AUROC and AUPRC, with beat and subject support (`08_evaluate.py`) |
| R6 | Honest reporting of F, S and Q limitations | Support (beats and subjects) is printed beside every per-class metric. The F/S/Q concentration and the Q lead confound go in the results text and limitations |
| R7 | Internal vs external clearly distinguished | Separate outputs (`mit_internal_*`, `incart_external_*`) and separate manuscript subsections; MIT-BIH is labelled "internal patient-grouped evaluation" |
| R8 | Preserve original and October outputs | All R2 output goes to `revision/R2/`; nothing outside it is written |
| R9 | Save configs, seeds, split hashes, checkpoints, logs and predictions | Per run: `config.json` (seed, subjects, counts, lock hash), per-learning-rate checkpoints and histories, `selected.json`, validation logits; one-time test and INCART logits in `results/scores/`; logs in `logs/` |
| R10 | No fabrication, selective omission or manipulation | Every run, learning rate and fold is reported, including failures. Scoring is write-once (`07_score.py` refuses to re-run). The evaluation code is frozen before scoring |
